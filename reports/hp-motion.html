hp-motion

Canvas tile badges and player chrome — provenance rendered inside the wall engine, at 60fps, with the pink identity carried all the way through.

Verdict

Both owned files shipped and committed. Registry tiles now carry lane provenance drawn inside the canvas — crisp at every zoom, DPR-aware, with the dirty-flag idle-zero discipline intact.

Three routed defects came in mid-lane and all three are fixed and verified live. Each turned out to be a one-line assumption with a large blast radius: the player forced CORS on every media fetch (most registry sources appeared dead); the wall never framed its content and its rows moved when other rows arrived (the registry — the product — sat off-camera on home); and resume was gated behind a threshold short sources can never satisfy.

Not verified: the LIVE chip, because no row in verified_sources.md carries the live marker. Code is complete and reachable; nobody has watched it pulse. Said plainly rather than papered over.

Built

js/wallview.js — canvas lane badges

  • badgeOf(item) reads lane/hls/live off an item with no app.js change: flat registry fields, a nested {meta:{…}} shape, or the emoji prefix on the title all resolve. Registry data is never mutated.
  • Chips draw in screen space, anchored to the tile's projected top-left corner, so they are never scaled or sheared — identical legibility at zoom 0.35 and at zoom 400.
  • Each (lane, integer height, dpr, labelled) chip is rasterised once into a small offscreen canvas and blitted 1:1 device-pixel. Crisp at any DPR, and the render loop does zero text shaping. Bounded LRU of 96, shared across WallView instances.
  • Collision ladder as a tile shrinks: labels drop first, then the HLS glyph. The lane chip and the LIVE chip are the claims themselves and never yield. Below ~7 px of chip height the layer fades out rather than becoming lint.
  • Lane-coloured tile edge drawn in tile space so it rides the shear with the poster it belongs to; widths divided by the tile's screen scale so the edge stays a constant number of screen pixels at every zoom.
  • Registry lane row headers wear the lane ink and a colour dot, so a row and the chips on its tiles read as one statement.
  • The selection caption strips a lane emoji prefix for display only — it should not repeat what the chip already says, and the item's own strings are never rewritten.
  • getState().badges exposes {badged, withLane, live, hls, pulsing} and every tile carries its badge, so budget row 6 is checkable without a screenshot.

js/player.js — P0 fix and chrome

  • P0: build() set video.crossOrigin = 'anonymous' unconditionally, forcing a CORS-mode media fetch, so every host without Access-Control-Allow-Origin died with MEDIA_ERR_SRC_NOT_SUPPORTED. Replaced with applyCORS(v, want), called before src is assigned and opt-in only via Player.play(opts.crossOrigin).
  • Seek bar with buffered band, revealed knob, hover time tooltip; focusable role="slider" with a real focus ring; consistent button states; title-block hierarchy; volume in the same accent language.
  • Lane badge chips in the top chrome driven by meta.lane, matching the canvas wall's lane inks, plus HLS and LIVE indicators — rendered only when the data actually provides them.
  • Motion eased ease-out-quart / ease-out-quint at 120–320 ms, with a prefers-reduced-motion block that collapses durations and stops the pulse.

Motion and the idle-zero contract

A pulsing LIVE chip is the only thing this feature adds that can keep the rAF loop alive. It is gated on a LIVE chip being actually visible, its dot is painted per frame over a cached chip body (one arc, never a re-rasterised chip), and when the wall is otherwise still the loop is capped at ~24 fps — a 1.5 s sine, so nobody can see the difference. prefers-reduced-motion kills it dead and restores idle-zero exactly. Everything else in the badge layer is static.

Pink identity completion

Routed from hp-trust's recon. C_THUMB_B #0b72d6 → #a81b52 (scrubber gradient), both rgba(56,163,245,.85) pill fills → a single C_ACCENT_ON token, and the player's rgba(56,163,245,.22) focus glow → pink. No blue survives from the CoolStremio lineage in either owned file.

Routed defects — the three one-liners

P0 · The player forced CORS on every media fetch

build() set video.crossOrigin = 'anonymous' unconditionally, which forces a CORS-mode media fetch, so every host without Access-Control-Allow-Origin died with MEDIA_ERR_SRC_NOT_SUPPORTED — four of six registry seed MP4s, all alive and all answering 206 to curl. It bought nothing on any path: a plain <video src> needs no CORS, and the hls.js/MSE path is fed a blob: URL so the element's attribute is irrelevant there. Audited before cutting — nothing in the file reads video pixels and no external <track> is fetched — then replaced with applyCORS(v, want), applied before src and opt-in only.

Side effect worth more than the fix: this falsified ADOPTED row 7. The canvas click always opened the player; the overlay simply had nothing to show because the media never loaded. A lane was about to fix a click path that was never broken.

P0 · The registry sat off-camera on home

Two independent causes, which is why a camera nudge alone would have regressed within seconds.

  • The camera never framed anything. catalogRows returns camera:null, so the camera stayed at its boot position (0,0) — which projects the first item to the centre of the screen, putting everything left of it and every row above the middle one out of frame. Layouts now return a homeCamera, applied only on an arrival: new content, or a layout the user just picked. A resize, row-count or order change is not an arrival and never yanks the camera. setItems compares the first tile's key, so the 2.5 s registry repaint does not re-home the camera under a user who has panned away.
  • Rows moved when other rows arrived. layoutCatalogRows centred the row stack on the origin, so a row's world position depended on how many rows came after it. Late-arriving Cinemeta catalogs slid every existing row upward and a stationary camera ended up looking at different content. Row 0 is now anchored at the world origin. That property is load-bearing precisely because the registry is watched live — rows really do arrive after the first paint.

The same reasoning killed a "centre it if it happens to fit" branch in homeCam: whether content fits depends on how much has loaded at that instant, and a home view that lands somewhere different depending on network timing is not a home view. That timing dependence was why the first attempt still opened on a Cinemeta row.

This also explains hp-quality's "whole wall renders black, chrome intact, no console error": with the camera parked where no content is, the wall correctly renders nothing. Honest limit: free pan into the void is the wall's deliberate doctrine — no clamp, no rubber-band — so a user can still pan to black on purpose. What is fixed is that it no longer happens at rest.

Accepted trade-off: framing the origin puts the first column at the viewport's left edge where persAmt() shear is strongest, so the leftmost tile is visibly skewed and its chip drops to glyph-only. That is the wall's designed edge behaviour plus the collision ladder working — and it is the price of showing the registry at rest instead of centring empty space.

Resume position was gated behind an unsatisfiable threshold

Continue-watching saved correctly but replay always started at 0. The save half was never the problem — maybeResume() refused to offer the position, behind if (!(pos > 30) …) return;. A flat 30-second floor is a good heuristic for a feature film. For short sources it is unsatisfiable: a 10 s clip can never hold a position above 30 s, and even a 52 s trailer stopped at 28 s falls below it. The prompt never rendered while localStorage held the right number the whole time. The floor is now Math.min(30, d * 0.05) — still a flat 30 s for anything ten minutes or longer, scaling down for short content; save()'s own 5 s floor got the same treatment.

Boundary held: the root cause was in player.js, not in app.js's meta handoff — the key matched and the record was found, the gate rejected it. No cross-file workaround was needed or written.

Also, for hp-trust

getState().tiles now carries scale — the tile's own layout scale, 0.34–1.15 across layouts — alongside k, so a DOM overlay anchored to a canvas tile can size itself without drifting.

  • Anyone adding a layout: a layout that wants to be framed on entry returns a homeCamera; one that does not simply omits it. The renderer still never learns a layout's name.
  • Whoever adds a live source: the LIVE chip keys off the word live in a registry row's Notes. Adding one is the whole test.
  • Future badge work: the chip atlas is keyed by (lane, integer height, dpr, labelled) with a 96-entry LRU. A fourth lane costs one entry in LANES and one glyph recipe — the renderer never learns its name, same extension-point discipline as the layout registry.
