4 · What the hardening changed

Law enforcement (relays)

  • signal.mjs — the message handler now drops any frame that is binary, larger than SIGNAL_MAX_BYTES (64 KB), or not a known-shape signaling JSON (_role/_ready/offer/answer/candidate or carrying sdp/candidate). The law is now enforced in our code, not left to peer good behaviour.
  • wss-broker.mjs — accountFrame still counts (for the proof) but now returns a violation verdict; the inbound handler ws.close(1003,'signaling-only') on any binary / non-protocol / oversized (>64 KB) frame. This both closes the "count-not-block" gap and caps per-frame SDP-smuggling. Live proof: normal announces peak ~4.9 KB, so no false rejects.

Honest measurement

// torrent.js — relayFileBytes is now measured, not asserted:
// bytes on any wire that is NEITHER a WebRTC peer NOR a web-seed. A relay is never a
// WebTorrent wire, so this is 0 by construction — but computed, so a regression shows up.
else { other++; otherBytes += (w.downloaded || 0); }

relayFileBytes: wb.otherBytes || 0

Browser client robustness (torrent.js)

  • Service-worker activation now races an 8s timeout → streamTo() rejects and the caller falls back to the engine instead of hanging forever.
  • A single finish() settle-point clears the timer and removes the client-error listener; an in-flight run now settles on a client 'error' instead of hanging to timeout.
  • Duplicate-torrent client errors are whitelisted as non-fatal (no more destroying the shared client + every other torrent); adds are deduped by infoHash first.
  • Timeout path destroys the orphaned torrent; the xs= fetch is bounded by an AbortController; empty/garbage magnets are rejected up front as bad-magnet.

Proof integrity

  • All 8 relay-punch harnesses self-locate ROOT via import.meta.url and resolve playwright repo-local-first (p2p checkout as fallback) — no more hardcoded foreign worktrees.
  • New prove-relay-negctl.mjs — the negative control that makes RELAY_FILE_BYTES=0 meaningful.
  • prove-rtc-killb.mjs + rtc-peer.html now sha256 the received bytes and compare to the source clip (end-to-end integrity, matching the wss proof).
  • panel-proof.mjs parses the relay line numerically (== 0) and documents that the authoritative zero-byte proof is the relay-side counter, not the displayed string.

6 · Honest UNVERIFIED / limits

  • Absolute vs shipped-client law claim. The relay hardening caps and drops oversized/binary/non-protocol frames, but a peer could still base64 a small payload inside a legitimately-sized SDP blob. Against the shipped, unmodified WebTorrent client (which never does this) the zero-byte law is proven; against an arbitrarily malicious modified peer it is bounded (≤64 KB/frame + connection-drop), not absolutely proven.
  • Real-browser edge cases (IndexedDB/OPFS full mid-download, tab-backgrounded timer throttling) were reasoned through and the hang/leak paths fixed, but not each reproduced live in a headless run — marked reasoned, not empirically reproduced.
  • The built-in /code-review //security-review //simplify slash gates were substituted by three dedicated Opus adversarial audit lanes (law/byte-path, correctness/edge-case, proof-integrity) run in parallel — higher-signal for this code, but a substitution, stated plainly.
  • hybrid-seed.mjs was reviewed statically (OK verdict) but not re-run live in this pass (it needs the classic BitTorrent swarm).
