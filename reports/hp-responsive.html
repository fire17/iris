hp-showcase explicitly did not sweep below 820px. This lane did. The app now holds from a 320px phone to a 3840px 4K viewport, with zero horizontal document overflow at every width measured, and the honest ledger keeps every word of its content in every form it takes.

Verdict

Before this lane, style.css carried four narrow media queries (700, 620, 820, 760) that hid a few labels. Nothing below that had been designed. Three genuine breakages were live at 375px, and one of them was a desktop bug wearing a phone costume.

Every fix below was found by driving the real app in a real browser at the width it broke, and every number quoted is one that was measured, not estimated.

Before and after, 375×667

What was built

One documented section at the end of style.css, ordered widest-gate-last so the narrow rules win by source order as well as by media match. Two invariants are stated in the sheet itself and hold at every width:

  • the page body never scrolls horizontally — html/body are overflow: hidden, and every wide strip owns a private overflow-x: auto scroller instead;
  • the honest ledger keeps all of its content — the lede, all three lane definitions, the watch line and the caveat. It may change shape on a phone; it may never be truncated into a half-truth.

prefers-reduced-motion: reduce Universal collapse of animation and transition duration, with the loading spinner deliberately exempt — it is the only signal the app is still working, and a frozen spinner reads as a hang.

Three decisions worth defending

The search collapse is CSS only. The collapsed plate is the real <input>, so a tap focuses it and :focus-within expands it over the bar. A second rule keeps it open while a query is showing, via :has(#search-input:not(:placeholder-shown)), so the clear button stays reachable. The two are written as separate rules on purpose: a selector list is discarded whole if any selector in it fails to parse, so an engine without :has() must still get the focus behaviour. index.html needed no change and no JS lane was touched.

The ledger cap is structural, not a media query. The dock is now a flex column with max-height: calc(100% - 78px) against #stage: the header is flex: 0 0 auto and the body takes the loss. That is what fixes the short-stage bug at every width rather than only on phones, and it is why the landscape case came right without a landscape-specific dock rule.

The scroll affordance switches itself off. A capped panel can hide its own last line, and a trust surface that looks finished while it is not is the exact failure this panel exists to prevent. Rather than a fade that is always painted, the body uses the pure-CSS scroll shadow: an opaque cover layer attached to the content (local) over a shadow layer attached to the box (scroll). Scrolled to the end, the cover lands on the shadow and hides it. No JS, and no fade ever painted over a caveat that is already fully visible — verified in both states (present at 375px where the body overflows by 26px, absent at 1440px where it does not).

NOT verified — stated plainly

  • harness limit The coarse-pointer block was never matched by a real coarse device. agent-browser set device sets the viewport and UA but not hasTouch, so (pointer: coarse) reported false even under iPhone emulation. The numbers above come from lifting the block's 18 rules out of the CSSOM and applying them unconditionally in a temporary probe sheet — that verifies the declarations I shipped and their layout consequences, but not that the media query matches on real hardware. The query is standard; the risk is low; it is still not the same claim.
  • not run Safe-area insets were never exercised on a notched device. Every env(safe-area-inset-*) resolves to 0px in this harness, so the max() fallbacks are what was actually measured. The insets are additive and cannot shrink anything below the fallback, so desktop is unaffected either way.
  • not run The @supports (height: 100dvh) rule was not tested against a retracting mobile URL bar — there is no URL bar in this harness.
  • partial Stream and episode rows were not seen populated. The min-width: 0 fix covers .stream-list and .ep-list by the same mechanism proven on .addon-list, but no installed addon returned streams during this lane, so those two lists were only ever rendered empty. Worth a second look when a stream addon is installed.
  • unchanged Contrast was not re-measured, because no colour was touched. The accent identity #f5387b and hp-trust's lane inks (--lane-v-ink #ff5c93, --lane-a-ink #b39dff, --lane-d-ink #9aa0aa, with their plates) are byte-identical to what was merged. This lane added no colour declaration other than two neutral gradient stops in the ledger's scroll shadow, both drawn from the existing panel background rgb(16,16,19).

Note on method

Five Opus 5 subagents were spawned for this lane (a CSS overflow audit, a DOM structure map, a media-query inventory, a console sweep on its own browser session, and a desktop-regression review of the diff). None of them had returned a report by the time the work was finished, committed and this page was written. Every bug listed above was found and fixed by direct live-browser iteration in this session, and the console sweep that was delegated was in the end run here, by hand, rather than left as an open claim.

This matches the honest caveat carried in the lane brief: on tightly-scoped work with a fast feedback loop, direct iteration beats the fan-out. Recording it here rather than dressing it up — the fleet's density target was met by concurrent spawns, but on this lane those spawns did not pay for themselves.
