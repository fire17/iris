The bug that mattered most

Found by reading, before any UI work: the data layer stamped hasMore unconditionally —

withHasMore(metas, !!(payload && payload.hasMore))

so a catalog payload that simply omits hasMore produced false, and the board's typeof res.hasMore !== "undefined" check read that as an authoritative "no more pages". The board declared itself exhausted after page one for every such addon. The live catalog payload here has exactly one top-level key — metas — so this addon was in that class. hasMore is now reported as the addon actually stated it: true, false, or null for "did not say", and null means keep paging until a page returns nothing new. Without this fix, no amount of filter UI would have produced a second page.

Protocol facts confirmed live (for the next lane)

  • Catalog payload top-level keys: ['metas'] only — no hasMore. Page size 101 for popular.
  • Meta key set: background, cast, country, description, genres, id, name, poster, posterShape, runtime, type, website. No videos, no released. posterShape: landscape.
  • Meta id form chaturbate:<room>, matching the manifest's idPrefixes: ["chaturbate"]. Colons survive URL encoding.
  • Catalog genre extras are not isRequired here, so the unfiltered catalog loads on its own.
  • access-control-allow-origin: * on the manifest — no CORS wall.
  • Manifest-level types are ["Adult","Live","Cam"] while the catalogs use type Chaturbate; the app keys off catalog type, which is why the type pill reads "Chaturbate".

The trap that cost the most time — recorded so nobody repeats it

Three separate false failures, all environmental, none in the code:

  • A background python3 -m http.server started without --directory bound to the main tree, not this worktree — an agent's bash cwd resets between calls. My edits were never under test.
  • After fixing that, the browser served js/app.js from its own HTTP cache (cache-busting the index.html query string does not bust separately-cached script URLs).
  • Port 8067 was already owned by another lane (serving scratchpad/appcopy2), so my server there failed silently and I was testing a sibling's stale copy.

The tell was a byte-size comparison: worktree app.js 74,732 bytes vs served 65,729 — identical to the main tree. Verify which bytes the browser is actually running before debugging behaviour. Final verification ran on port 8078, confirmed byte-identical to the worktree.

One consequence to flag: an earlier server on port 8066 was killed to rebind it. It was started in this session, but it may have been a sibling lane's process — if another lane lost a server on 8066, that was me. Ports 8077 and 8078 are mine and can be reaped.

Handoffs

  • The one settings line. previewManifest() now normalises via window.Addons.manifestUrl(url) and passes the normalised url onward to install(). It is commented in place as a handoff note. Nothing else outside the board region was touched.
  • Filter-bar markup and CSS are injected from JavaScript (#hp-filterbar, one <style id="hp-board-css">) precisely so this lane owns no lines in index.html or style.css while siblings were editing both. Folding them into the static files is a clean, behaviour-neutral follow-up.
  • Per-tile external marking currently rides the title glyph, matching the existing registry convention (registry.js prefixes its lane badge into the item name). A richer per-tile treatment belongs in wallview.js, which this lane did not own.
  • Multi-select filters. optionsLimit is parsed and carried through but the UI selects one value per extra. Catalogs declaring optionsLimit > 1 could offer multi-select.
