1 · What shipped

The core inversion — playable beats external, always

A Chaturbate cam item carries three streams: 720p HLS, 540p HLS, and a redundant Chat Now! externalUrl (always last). The old flow could bounce the user to chaturbate.com — a page that can't even be iframed (x-frame-options: SAMEORIGIN). The fix: stream selection prefers a playable in-browser source (HLS / direct file / torrent-via-engine) and excludes externalUrl entirely. The cam's own low-latency HLS plays in our overlay; the external link is only ever reached when nothing playable exists.

Three in-house viewing tiers

PREVIEW · hover→ GLANCE · ⤢ button / bigger look→ WATCH · full screen + sound
  • Preview — hovering a tile with a playable stream starts a muted, playsinline, live-edge inline <video> anchored over the tile, after a 180 ms debounce. Live streams use hls.js lowLatencyMode + a seek to liveSyncPosition; short VOD clips loop. A poster/live-thumb covers the frame until playback starts; a LIVE chip pulses in the corner.
  • Glance — the ⤢ button on the preview (or programmatically) expands the same muted stream into a larger, centred player over a scrim — a look between hover and commit. Dismisses on Esc or a click on the scrim.
  • Watch — the ▶ button opens the full-screen Player overlay, unmuted, with the full control chrome. Muted-only until this explicit click (autoplay-policy clean).

The clean external hand-off

When an item is genuinely external-only, the player no longer apologises. No pre-emptive window.open-then-"we got blocked". Instead a confident card: "Watch on <Site> ↗" with a real anchor "Open on <Site> ↗" (target="_blank" rel="noopener noreferrer") — a user-gesture anchor click is never pop-up-blocked. The site name is derived from the URL host (chaturbate.com → Chaturbate).

Live-stream resolution chain (graceful degrade)

registry hpUrl (instant)·or· hp-resolver :11471 (fresh LL-HLS)→ Addons.streams HLS→ clean external ↗
  • Registry rows (verified_sources.md) are their own stream — hpUrl, with hls/live flags threaded straight into the player.
  • Known-site cams (chaturbate:<room> id) resolve FRESH each preview/play via GET :11471/resolve?site=chaturbate&room=… (tokens are single-shot — never cached long; TTL 12 s, well under the resolver's 30 s+ grace). Generic non-CORS sources fall back to the resolver's proxyUrl.
  • Resolver down or ok:false (offline/private/away) → the item's addon-provided HLS → the clean external card. The app works fully with the resolver and the engine absent.

Torrentio / torrents in-house

The existing webtorrent engine path (server/engine.mjs, :11470) is preserved: infoHash streams play in-house when the engine is up, and degrade to a clean copyable-magnet affordance (magnet + "run the local engine" hint) when it isn't — never the apologetic popup.

2 · The hover-preview design (leak-safety is the load-bearing part)

The invariant: at most ONE preview <video> and ONE hls instance alive at any instant, no matter how fast the cursor sweeps the wall. The design that guarantees it:

  • Single owner. The inline video + hls live entirely in player.js (Player.preview/glance/previewStop), reusing its existing hls.js loader. One module owns start & teardown, so there is one place to get cleanup right. Preview and glance share the same singleton surface (glance replaces preview).
  • Synchronous teardown before replace. pvStart() calls pvStop() first. pvStop() destroys the hls instance and removes the <video> node from the DOM immediately (the empty wrap fades out afterward for looks) — so the live count drops this tick and never shows a transient "2 videos" during a fade.
  • Debounce + race token. A hover waits 180 ms before starting; every hover bumps a token; an async stream-resolve that returns after the cursor moved on is dropped (token / hoverIdx mismatch). Re-hovering the already-active tile is a no-op.
  • Teardown on every exit. Mouse-out (onHover(null,-1)), select, route change, wheel-pan, resize, and opening the full-screen player all call previewStop(). Player.play() also stops any preview (singleton across all modes).
  • Layered, never drawn into the canvas. The preview is a position:fixed DOM element over the canvas wall (pointer-events:none except its two buttons), so the wall keeps its 60fps feel and hover/click fall through to the canvas.
  • Geometry from the wall's own state. The tile's on-screen rect comes from WallView.getState().tiles[i] (sx,sy,k,scale,dw,dh) + the canvas client rect — no guessing, no wallview edit.
  • prefers-reduced-motion. Honoured literally: no autoplaying video — the still poster/first-frame only. Zero video, zero hls, zero leak.
  • Caching. Resolved streams cache by item id — registry forever, live tokens 12 s — so re-hover is instant without reusing a dead token.

4 · Integration notes for the fleet

  • For hp-nav (100s-preview split): the shared per-item field is liveThumb — hp-stream sets item.meta.liveThumb (and item.liveThumb) from the resolver's thumb when it resolves a cam; the cheap many-thumbnail refresh should read the same field (or the resolver's /thumb?site=chaturbate&room=… primitive). hp-stream owns only the ONE focused motion preview for the tile under the cursor.
  • Resolver contract consumed: GET :11471/resolve?site=chaturbate&room=… → {ok,kind:"hls",url,live,thumb,corsSafe,proxyUrl?}; /health probed with an 800 ms timeout and 8 s cached down-state. Resolve is fresh per preview/play; GET-only (a HEAD would void the token — hls.js is GET, safe).
  • Read-only test seam: window.HP exposes wallState() · wallList() · tileRect(idx) · previewStats() · activePreview() · resolverUp() for verification and future darwin rounds — reads live state only, changes no behaviour.
  • Public player API added: Player.preview(opts) · previewStop() · glance(opts) · glanceStop() · isInline() · inlineStats() (version bumped 1.0.0 → 1.1.0).

5 · Known limitations & honest UNVERIFIED marks

  • A real Chaturbate cam playing end-to-end in-house is proven by mechanism (identical HLS path as the Mux row + resolver confirmed returning CORS-clean LL-HLS masters), and smoke-tested to scratchpad only per scope law — not committed as evidence (repo stays zero-adult-content). The committed proof is the SFW Mux live row.
  • Torrent playback is real P2P and peer-dependent; the engine path and magnet fallback are verified, but a given torrent's time-to-first-frame varies — see the hp-v-torrent result.
  • Preview anchoring ignores the wall's per-tile perspective shear (edge tiles) — the preview is its own axis-aligned lifted box by design, not a pixel clone of a sheared tile. The focused/centre tile has ~0 shear.
