the whole interface

The three commands

(a) Start the collector service

node beta/keygen.mjs            # once: mint the keys, print the public JWKs to pin in js/hp-beacon.js
beta/run.sh start               # supervise the collector — restarts it forever, returns immediately
beta/run.sh status              # supervisor PID + collector PID + log paths
beta/run.sh stop                # stop both; leaves no process and no PID files
beta/run.sh log                 # tail -F collector.log and run.log together

Everything honours IRIS_BETA_HOME (default ~/.iris-beta), so a throwaway store costs nothing: IRIS_BETA_HOME=/tmp/ib-test beta/run.sh start.

(b) Watch the realtime feed

// the line to arm as a Monitor — major events only, heartbeats never enter this file
Monitor({persistent: true, command: 'beta/watch.sh', description: 'iris beta realtime'})

// if even the major feed is too loud, re-arm with a filter — never widen the feed itself
Monitor({persistent: true, command: "beta/watch.sh 'error|fail|heal'", description: 'iris beta errors'})

From a shell it is just beta/watch.sh, or beta/watch.sh -n 40 to replay the last 40 lines before following.

(c) View the roster board

node beta/board.mjs             # once
node beta/board.mjs --watch      # redraw every 5s
node beta/board.mjs -n 40        # longer feed tail
node beta/board.mjs --no-feed    # roster only

seams found after beta/collector.mjs landed

Two fixes the acceptance list would not have caught

1 · The roster shape was not what the contract said

COMMON.md specifies cid → {first, last, where, state, counts} with ms-epoch stamps. beta/collector.mjs:167-205 actually writes ISO strings for first/last and state as an object {view, playing, ih, buf, engine, healN, dropped, at}, plus cpk, sid and last_major. Rendered naively that is NaN ages and [object Object]. board.mjs now accepts both stamp forms, renders the state object as the DOING column (▶ player hls, · home, left player webtorrent), flags client-side drops, counts remote-testable clients, and reads status.json for its header line.

2 · Every collector line was being logged twice

beta/collector.mjs:79-85 appends each line to collector.log itself as well as printing it, so the supervisor's >> collector.log redirect duplicated the whole service log. The child's raw stdout/stderr now goes to run.log — which is where a node startup crash or stack trace lands, the output that dies before the collector's own logger exists — while collector.log keeps the collector's lines plus the supervisor's [run] lines. beta/run.sh log tails both.

the law these scripts keep

Security model, in one paragraph each

  • No inbound surface. No listener, no port bind, no EXPOSE, no -p. Browser and collector both dial out to a neutral broker, so neither learns the other's address and nothing on the internet can reach this host — the same one-way law as dispatcher/.
  • Sealed, not merely "on a private room." The floor's room key derives from the room name and that name ships in public JavaScript, so every event is additionally sealed to the collector's key (ECDH P-256 + HKDF + AES-256-GCM). A wrong key stores nothing — proven above.
  • No PII. The where block is {tz, lang, platform, mobile, screen, conn}. No IP, no precise geolocation, no account, no cookie, no fingerprint — and the store never leaves the machine.
  • A visitor can see it and switch it off in one click — the beta pill, or localStorage.setItem('hp.beta','0'). Off means the beacon sends nothing at all, and the C2 uplink is dead too because it rides the same switch.
  • Remote control is signed, allowlisted and visible — never silent. The browser shows a remote-test indicator whenever a command runs.
  • These three scripts cannot be an attack surface. They read the store and their own PID files, interpolate no inbound value into anything, run no command derived from telemetry, and never touch priv.jwk or ctrl_priv.jwk.

handoffs

What the next session or lane needs to know

  • Nothing is installed and nothing was pushed. The launchd plist is staged; the supported way to run the service is beta/run.sh start, which needs no root and leaves nothing behind after stop.
  • Docker is the one unproven artifact. Bring up colima (or install buildx) and run the piped-tar recipe; that is the only step left to close it.
  • The store contract gained files beyond COMMON.md's list: status.json (collector counters, which the board's header reads), ctrl_pub.jwk/ctrl_priv.jwk (C2 signing), and the supervisor's run.log/run.pid/collector.pid.
  • No floor copy lives in this lane. board.mjs imports only node:fs, node:path, node:os; run.sh and watch.sh are shell. The Dockerfile copies the canonical vendor/hp-floor.mjs, so the relay-underflow fix (0494347) is picked up with no re-sync — verified in sync with beta/hp-floor.mjs and dispatcher/hp-floor.mjs.
  • One field note for the collector and verify lanes: a live run showed relays=1 (0 → 1 over ~8s) rather than the oracle probe's expected relays: 2. That observation predates 0494347, which fixed exactly this counter, so it is likely already answered — worth one confirming probe.
