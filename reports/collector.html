What this lane built

FileWhat it is
vendor/hp-seal.mjsThe shared sealed envelope, imported by the beacon lane. ECDH P-256 → HKDF-SHA256 → AES-256-GCM, isomorphic (browser + Node 22+), zero dependencies, no imports at all. Wire: [0x01][65B ephemeral raw pub][12B iv][ct+tag]. A fresh ephemeral keypair per message, and the ephemeral public key doubles as the HKDF salt, so every event derives its own AES key. openWith never throws.
beta/keygen.mjsMints both keypairs: the ECDH sealing pair (priv.jwk, 0600) and the ECDSA control pair (ctrl_priv.jwk, 0600). Prints either public JWK for pinning in the client. Refuses to clobber without --force, because a silent rotation would blind every deployed client.
beta/collector.mjsThe daemon. Joins the floor room, opens sealed events, validates hard, appends to events/<UTC-day>.jsonl, maintains the derived roster, and writes MAJOR events only to realtime.log with 60-second coalescing.
beta/query.mjsReads the store back: status · clients · tail (--since --client --kind --grep --major --limit) · top. Read-only; scrubs every value it prints.
beta/cmd.mjsThe command half. One signed, sealed frame to a live browser, then it prints whatever comes back matched by nonce.
beta/hp-floor.mjsByte-identical copy of vendor/hp-floor.mjs, the way dispatcher/ vendors it. Carries the orchestrator's relay-counter fix (0494347); this lane never edited it.

Defects found and fixed while verifying (each caught by running the real thing)

  • Relay counter underflow in the shared floor — down() decremented the shared live counter even for a socket that never opened, so each failed retry against the dead relay cancelled the healthy relay's increment and relays decayed to 0 while data flowed fine. Outside this lane's owned paths, so it was reported, not patched; the orchestrator fixed it in 0494347. --probe now dials each relay itself and waits for a real CONNACK, so the number it prints cannot be a shared-counter artifact.
  • rx was persisted as epoch milliseconds while both query.mjs and the crash replay parsed it with Date.parse. query status reported zero events while the JSONL held them. Now an ISO-8601 string.
  • Roster drifted across a crash — cmd_sent is written locally by cmd.mjs and never crosses the wire, so the live collector could not count it while a restart replayed it. cmd_sent is now excluded from the roster (still fully stored and queryable), making the roster deterministic.
  • Roster/status flush was 10s, so query clients could be stale right after an event. Now 2s.
  • The closing ×N line reused the first event's timestamp, so a line appearing now bore a minute-old time. It is now stamped when the window closes.

Security posture

  • Outbound only. No inbound port, no HTTP server, no listener. floor.send is never called from the collector; commands leave through cmd.mjs, a separate short-lived process the operator runs deliberately.
  • Injection-immune. No shell, no eval, no fetch, no child process. Filesystem writes are confined to $IRIS_BETA_HOME at paths built from our own clock and fixed names — never from a frame. Inbound strings are control-character scrubbed before reaching any log line.
  • Bounded. Frames over ~9 KB dropped, plaintext over 8 KB dropped, every string truncated to 500 chars, arrays capped at 100, object keys at 50, depth at 6, ids at 64 chars, dedup LRU at 10k.
  • Crash-proof. Global uncaughtException / unhandledRejection guards, every frame handled inside try/catch, derived state rebuilt from the day's JSONL on start.
  • C2 cannot be widened by data. The verb list is a fixed twelve-entry allowlist; there is no eval and no arbitrary-JS command at any rev level. Commands are signed with a key that never leaves this machine, and each is sealed to one client's own public key.
  • Privacy. Nothing derives or stores an IP or precise location; where is the coarse client-declared set and nothing more.

DEFECT-3 (filed by the verify lane) — not this lane's fix, but there is a free mitigation

The root cause is in js/hp-beacon.js and vendor/hp-floor.mjs, neither of which this lane owns, so it was not patched here. beta/cmd.mjs is only where the symptom surfaces: a client with no cpk cannot be commanded. The collector accepts cpk from any event, not only join (collector.mjs:178) — so attaching cpk to the heartbeat makes a client commandable even when its first join is destroyed.

Verified live: a stand-in client that never sent join at all, only a heartbeat carrying cpk, appeared in the roster with c2: yes and answered a ping — <- nojoincl pong {"rtt_ms":253} and <- nojoincl ack {"cmd":"ping","ok":true}. cmd.mjs's refusal message now names DEFECT-3 and both remedies.

The client's cpk must be an ECDH P-256 public JWK and should arrive in join; command responses come back as ordinary sealed telemetry carrying the nonce.

  • Ops lane: beta/run.sh should restart-loop node beta/collector.mjs; the daemon writes status.json every 2s, so a stale updated is the liveness signal (query.mjs status flags it).
